# A11y Static Audit — 2026-04-18

Static WCAG 2.1 AA audit of `components/` and `app/` (excluding `content/articles/`). No browser tooling — grep + file inspection only. Ratios not computed; suspect pairings are flagged, not proven.

## P0 (blocking users)

- **app/page.tsx:350–355** — Homepage newsletter `<input type="email">` has no `aria-label`, no `<label htmlFor>`, no `placeholder` that serves as a name. Screen readers will announce "edit, blank". Also inside a `<form>` with no `onSubmit` handler and no submit-button `aria-label` conflict, but the unlabeled input is the blocker. Fix: add `aria-label="Email address"` (match sibling `NewsletterSignup.tsx` pattern).

- **components/Search.tsx:200–207** — Global search modal `<input type="text">` has `placeholder="Search articles..."` but no `aria-label`. Placeholder is not an accessible name per WCAG. Fix: add `aria-label="Search articles"`. The dialog container at line 190 also lacks `role="dialog"` and `aria-modal="true"`, and clicking outside closes it but there is no `Escape` key handler tied to the dialog role — combined with missing focus-trap this is a P0 modal-accessibility issue.

## P1 (WCAG AA fail)

- **app/globals.css** — No `@media (prefers-reduced-motion: reduce)` block anywhere in the stylesheet. Components animate via `transition`, `transform`, and `opacity` (e.g. `FeaturedCarousel` auto-rotates every 6s, `CookieConsent` slides in, `BackToTop` fades, `ScrollProgress` animates on scroll). WCAG 2.3.3 (AAA) plus 2.2.2 (AA) implications. Fix: add a global `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; animation-iteration-count: 1 !important; scroll-behavior: auto !important; } }` to `globals.css`.

- **components/FeaturedCarousel.tsx:26–30** — Auto-rotating carousel with 6s interval, pauses only on `mouseenter` (not on focus, not on `prefers-reduced-motion`). Keyboard users and screen-reader users cannot pause rotation. WCAG 2.2.2 fail. Fix: (a) pause on focus-within, (b) respect `prefers-reduced-motion`, (c) add an explicit pause/play toggle button.

- **components/NewsletterSignup.tsx:69, 122 + InlineNewsletter.tsx:68 + CalendarBrowser.tsx:102, 158 + app/page.tsx:353** — Multiple inputs/selects use `className="...outline-none"` with no matching `focus-visible:ring-*` or `focus-visible:outline-*` utility. Keyboard focus is invisible. WCAG 2.4.7 fail. Fix: append `focus-visible:outline-2 focus-visible:outline-orange-500 focus-visible:outline-offset-2` or equivalent ring utilities.

- **components/Search.tsx:206** — Modal input uses `focus:outline-none` with no `focus-visible:` fallback. Same WCAG 2.4.7 issue inside the modal.

- **components/NewsletterSignup.tsx:145** — Footer copy `color: 'rgba(255,255,255,0.35)'` on `#14213d` navy. Luminance ratio is below AA for normal text — suspect contrast fail. Fix: bump alpha to at least `0.6` or use `#9ca3af`.

- **components/Footer.tsx:59, 129** — `rgba(255,255,255,0.5)` small copy on `#14213d`. 12px/14px text at 50% white on navy is borderline / likely AA fail for small text. Fix: raise to `0.7`+ or use a solid neutral.

- **components/Search.tsx:185** — `text-gray-400` ("⌘K" hint) on what appears to be white/light header bg — likely AA fail for 12px text. Fix: `text-gray-500` minimum.

- **components/Breadcrumb.tsx:42** — `text-gray-400` separator on white is OK for decorative `/` but the adjacent breadcrumb text also uses muted colors; verify `text-gray-500`+ on crumb anchors.

- **components/CalendarBrowser.tsx:153** — `<label>` wrapping a `<select>` with no `htmlFor`. Implicit label is accepted by AT, but spec-strict (and some older SR) prefer explicit association. Acceptable but consider adding `htmlFor="sort-select"` + `id="sort-select"` for robustness.

- **components/MDXImage.tsx:32, 56** — `const altText = alt || ''`. When `alt` is missing from MDX, the image renders with empty alt. For purely decorative images this is correct, but fallback path line 56 emits `<img src alt="">` for *any* unknown local image. Missing alt in source markdown will silently become empty alt on the rendered page. Fix: throw/warn in dev if `alt` is falsy, or emit a visible warning comment.

## P2 (best practice)

- **app/layout.tsx:89** — `<html lang="en">` is correct. Good.

- **components/Header.tsx:149–181** — Icon-only mobile buttons all have `aria-label`. Good. But the hamburger `aria-expanded` is set — missing `aria-controls` pointing to the mobile nav id. Fix: add `id="mobile-nav"` to the `<nav>` on line 187 and `aria-controls="mobile-nav"` on the button.

- **components/Header.tsx:66** — `className="... h-15"` is not a valid Tailwind class; height is enforced by inline `style={{ height: '60px' }}`. Not a11y, but worth cleaning up.

- **components/FeaturedCarousel.tsx:152–164** — Dot indicators have `aria-label={\`Go to slide ${i + 1}\`}` but no `aria-current="true"` on the active dot. Fix: add `aria-current={i === current ? 'true' : undefined}`.

- **components/FeaturedCarousel.tsx:78** — `<Link>` wraps the entire slide including the "Read Article" `<span>` styled as a button — nested interactive fine since the span is not a real button. OK, but the outer slide `<div>` at line 45 has an `onClick`-style link through Link — a keyboard user Tab lands on the outer link then still needs to Tab past prev/next/dots. Consider a skip mechanism.

- **components/CookieConsent.tsx:36–40** — `role="dialog"` with `aria-label="Cookie consent"` but no focus management — the dialog appears 1s after load and does not move focus. Low-severity (it's a banner, not a modal), but consider `role="region"` + `aria-live="polite"` instead of `dialog`.

- **components/GoogleMap.tsx:54–63** — `<iframe title={title}>` with default `title="Map"` — fine, but if multiple maps on a page they'll all share the same title. Encourage unique titles.

- **components/TableOfContents.tsx** — `<nav aria-label="On This Page">`. Good.

- **components/BookmarkButton.tsx:70** — button has `aria-label` that flips with state (`Saved` / `Save article`). Good.

- **components/ShareButtons.tsx:71–111** — every share `<a>` has `aria-label`. Good.

- **components/BackToTop.tsx:32** — `aria-label="Back to top"`. Good.

- **components/ThemeToggle.tsx:54** — dynamic `aria-label`. Good.

- **Icon-only buttons generally** — Header hamburger, search, theme toggle, back-to-top, bookmark, share, carousel prev/next/dots, cookie accept/decline, all scanned — all have `aria-label` or visible text. No icon-only buttons missing accessible names found.

- **components/ArticleCardV2.tsx, ArticleCard.tsx, AuthorBox.tsx** — all `<Image>` uses pass an `alt` prop (falls back to `article.title` or `AUTHOR.avatarAlt`). No empty-alt images found in components. Good.

- **Heading hierarchy** — `<h1>` grep across `components/**.tsx` returned zero matches. H1 is emitted only by page/layout files. Good.

- **Form label coverage** — only `FeedbackForm.tsx:128` uses `htmlFor`; all other inputs (newsletter variants, search bars, calendar search) rely on `aria-label`, which is WCAG-sufficient. Visible-label coverage could be improved for clarity.

## Passes

- Skip-to-content link exists: `app/layout.tsx:170` — `<a href="#main-content" className="sr-only focus:not-sr-only ...">Skip to content</a>` with matching `<main id="main-content">` on line 176.
- `<html lang="en">` set on root.
- `app/search/page.tsx:91` has a proper `focus-visible:outline-*` pattern (only input with correct focus style).
- `components/FeedbackForm.tsx:135` uses `focus:outline-none focus:ring-2 focus:ring-orange-500` — correct replacement pattern.
- No `<img>` / `<Image>` tags with empty or missing alt in scanned components.
- All SVG icons inside interactive elements have `aria-hidden="true"` (Header, BackToTop, hamburger).
- Icon-only buttons all have `aria-label`.
- No duplicate `<h1>` risk from components.
- `viewport` metadata allows zoom: `maximumScale: 5` (not locked to 1) — WCAG 1.4.4 respected.
- `prose a` has visible underline (`border-bottom`) — link identification independent of color. Good.

## Recommended next (ordered by impact)

1. **Add `prefers-reduced-motion` guard** to `app/globals.css` (one global block). Unblocks vestibular-disorder users and is the highest-impact single fix.
2. **Fix the two P0 unlabeled inputs**: `app/page.tsx:350` newsletter input and `components/Search.tsx:200` modal input — add `aria-label`. 2-line diff.
3. **Replace bare `outline-none` with `focus-visible:outline-*`** across `NewsletterSignup`, `InlineNewsletter`, `CalendarBrowser`, `app/page.tsx`, and `Search.tsx`. Six locations, mechanical fix.
4. **Harden Search modal**: add `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, focus trap, and `Escape`-to-close. Without this, keyboard users cannot exit.
5. **Raise white-alpha contrast** in footer + newsletter small copy from `0.35`–`0.5` to `≥0.6` on the `#14213d` navy background. One-line CSS change per occurrence.
