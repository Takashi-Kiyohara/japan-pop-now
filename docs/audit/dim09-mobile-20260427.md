## Findings

### P1 — `/articles` returns 404 (BottomNav broken target)
The "Articles" tab in BottomNav (`/articles`) has no corresponding `app/articles/page.tsx`; only `app/articles/[slug]/` exists. Mobile users tapping the BottomNav Articles tab hit a 404. This is a high-impact mobile UX defect: a 5-tab nav with one broken tab is a 20% navigation failure rate.

**Auto-fix recommendation (PR, ~30 min):**
- Create `app/articles/page.tsx` rendering an article index (filterable by category, paginated). Reuse `ArticleCardV2` and the same data source the silo hub pages use.
- Or: update `components/BottomNav.tsx` to point Articles tab to an existing route (e.g. `/category/area-guides` or `/guides`).

### P2 — Header mobile buttons below 44px
Mobile search button + hamburger button each use `p-2` (8px padding) on a 20px icon = ~36px tap zone. WCAG 2.5.5 AAA guidance is 44px minimum.

**Auto-fix recommendation (PR, ~10 min):**
- Change `p-2` to `p-2.5` (10px) plus `min-w-[44px] min-h-[44px]` in `components/Header.tsx` lines 148 and 164.

### P3 — MDXImage lacks srcset
`MDXImage` returns a plain `<img>` with `loading="lazy"` but no `srcset`/`sizes`. On mobile the full-resolution body image is downloaded. Featured/hero images are fine (next/image). Body image WebP files in `public/` are likely 1200px+; mobile would benefit from a 640w/750w variant.

**Auto-fix recommendation (PR, ~45 min):**
- Replace MDXImage's `<img>` with `next/image` (`fill` or with explicit width/height extracted from frontmatter or filesystem). Keep the `rounded-lg` and lazy loading. This will auto-generate srcset for all body images. Risk: width/height required for `next/image` — may need a small lib helper to read image dimensions at build time.
