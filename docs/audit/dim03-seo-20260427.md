## Issue inventory

### P1-A — Title duplicated `| Japan Pop Now` suffix (8 pages)

Root cause: `app/layout.tsx` sets `metadata.title.template = "%s | Japan Pop Now"`. Pages that already include `— Japan Pop Now` (or `| Japan Pop Now`) in their string title get the suffix appended a second time.

| Path | Current title | Source file |
|---|---|---|
| `/calendar` | `Anime Events & Collab Cafe Calendar Japan 2026 \| Japan Pop Now \| Japan Pop Now` | `app/calendar/page.tsx:14` |
| `/features` | `Feature Series \| Japan Pop Now \| Japan Pop Now` | `app/features/page.tsx:7` |
| `/about` | `About Us — Meet the Japan Pop Now Team \| Japan Pop Now` | `app/about/page.tsx:8` (only contains brand name once but matches pattern) |
| `/search` | `Search — Japan Pop Now \| Japan Pop Now` | `app/search/layout.tsx:9` |
| `/support` | `Support Japan Pop Now — Buy Us a Coffee \| Japan Pop Now` | `app/support/page.tsx:5` |
| `/category/{slug}` (all 5) | e.g. `Pop Culture — Japan Pop Now \| Japan Pop Now` | `app/category/[slug]/page.tsx:101` |
| `/cafes` | `Anime Collab Cafes in Japan — Japan Pop Now \| Japan Pop Now` | `app/cafes/page.tsx:27` |

**Fix:** Use `title: { absolute: '...' }` for these pages to bypass the template, or remove the embedded `— Japan Pop Now` / `| Japan Pop Now` and let the template add it once. About/Support cases are softer (brand name appears only once visibly) but still create awkward double-brand SERPs.

### P1-B — `og:url` ≠ canonical (8 pages)

Root cause: Static pages set `alternates.canonical` but do **not** set `openGraph.url`. Next.js falls back to the root layout's `openGraph.url = "https://www.japan-pop-now.com"`, so every static page reports `og:url = https://www.japan-pop-now.com`.

| Path | canonical | og:url |
|---|---|---|
| `/search` | `…/search` | `…/` |
| `/features` | `…/features` | `…/` |
| `/about` | `…/about` | `…/` |
| `/contact` | `…/contact` | `…/` |
| `/privacy` | `…/privacy` | `…/` |
| `/affiliate-disclosure` | `…/affiliate-disclosure` | `…/` |
| `/support` | `…/support` | `…/` |
| `/category/events` | `…/category/events` | `…/` |

**Fix:** Add `openGraph.url` matching the canonical, or define a metadata helper. Categories use `app/category/[slug]/page.tsx` — that file *does* set `openGraph.url` (line 113), so the events case is likely a stale-cache artifact (see also note D below).

### P1-D — `/category/events` indexable despite zero articles

`/category/events` has `robots: index, follow`, but `getArticlesByCategory('events')` returns 0. The metadata code in `app/category/[slug]/page.tsx:106` should set `noindex` when articles.length === 0 — and **does** for `/category/culture` (also empty, correctly returning `noindex, follow`).

Most likely cause: stale ISR cache (`revalidate = 3600`) from before the `noindex` code was deployed *and* before the last events-category article was demoted/recategorised. Will self-heal at next revalidate; flagging so the next deploy or `/api/revalidate` cycle cleans it. Not an auto-fix candidate.
