## Contact-address rule (critical)

Every template uses the same safety protocol:

- Only emails / URLs **literally present in the live WebFetch response
  body** appear in research files and templates
- Companies whose sites returned 403 (bot protection) or whose pages had
  no contact info are marked **⚠️ SEND TO: [press-page URL]** — Takapon
  browser-loads and confirms the actual destination before sending
- No contact address has been transcribed from WebSearch's synthesized
  summary (WebSearch synthesis proved unreliable in the JNTO test — it
  offered `media_inquiry@jnto.go.jp` which does NOT appear on JNTO's
  live pages)

## Takapon UX guarantee

Each `templates/{slug}_{lang}.md` file contains:

1. A **⚠️ SEND TO** header pointing to the verified destination URL —
   Takapon clicks through, confirms the destination, pastes the body
2. The email body (subject + message) fully composed with article-
   specific details pre-filled
3. A **Submission checklist** for any manual step (dropdown selection,
   dashboard login, etc.)
4. An **Article context** section noting current density and image need

**Zero hallucinated emails.** Every "⚠️ browser-load" marker exists
precisely because the automated fetch could not confirm a live address,
not because the address might be wrong. This preserves "copy and send"
UX without risking fake-destination sends.
