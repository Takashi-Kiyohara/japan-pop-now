### R-2 sitemap.xml に 410/404 URL を残すな
Mueller 公式: main sitemap.xml に 410/404 は残さない (temporary sitemap-removed.xml 別)、Phase 4 verify「sitemap URLs all 200」gate が intentional 410 で永久 fail する。

- ref: https://www.seroundtable.com/404-sitemaps-google-removal-26926.html

### R-7 middleware.ts redirect 配置 conflict
middleware が higher precedence、next.config.ts redirects は build-time `routes-manifest.json` 焼き込み middleware 後評価。R18 P5 の `Cache-Control: private/no-store` が middleware にあるため、redirect 系を middleware に増設すると redirect path にも private/no-store 載って Vercel edge cache 効かず TTFB +50-150ms。
**修正**: 全 redirect (legacy WP + chain 1-hop 化) は **next.config.ts** 側に集約、middleware には書かない。middleware の Cache-Control は path filter で `/api/*` 等に限定、redirect path 除外。
- ref: https://github.com/vercel/next.js/discussions/70365

## YELLOW

### Y-1 Next.js 16 410 Gone 実装
App Router の `page.tsx` から 410 を返す native API 未実装、`notFound()` は 200 streamed / 404 non-streamed で 410 にならない。
**修正**: legacy WP slug は `app/(legacy)/[...slug]/route.ts` 新設、`new Response('Gone', { status: 410, headers: { 'Cache-Control': 'public, max-age=31536000' } })`。middleware rewrite で 410 status workaround 禁止 (edge cache が status 200 誤キャッシュ報告)。
- ref: https://github.com/vercel/next.js/discussions/86345

### Y-3 canonical false positive
Vercel preview deploy URL (`*.vercel.app`) で render すると canonical が production を指す、preview 上で実行すると全件 mismatch 誤判定。
**修正**: Phase 1 curl は production `https://www.japan-pop-now.com/*` のみ、Googlebot UA 固定 (memory `feedback_curl_ua_bot_defense`)、preview URL exclusion。canonical 検出は `<link rel="canonical">` regex extract、normalize (trailing slash 揺れ等) 後 strict equal。
- ref: https://nextjs.org/docs/app/api-reference/file-conventions/metadata

### Y-4 GSC reflect lag 実測値
2025 公式 lag 通常 2-4 日、normal 下限 24-48h、ただし 2025/11-12 freeze 障害 spike 残存報告。「5/22 で 8-15 件」は理論 OK だが claim aggressive。
**修正**: KPI を「5/22-5/29 window で indexed 5-12 件」に幅広げ、**5/25 + 5/29 + 6/5 の 3 段階観測**、Pages indexing API live test 併用。
- ref: https://almcorp.com/blog/google-page-indexing-report-delay-fixed/

### Y-5 legacy WP 410 vs sitemap 除外 logic
Mueller: 410 と 404 はほぼ等価、speedup は数日のみ。優先順は (a) sitemap 除外 → (b) 410 返却 → (c) temporary removal sitemap → (d) GSC URL removal tool。`/category/anime/` は default 404 で十分、410 化不要。
**修正**: 410 化対象 = `?p=NNN` / `?page_id=NNN` / `/wp-content/*` の WP-only パターン限定、`/category/*` は何もしない (default 404) を Phase 2 で明文化。

### Y-6 1-hop 化後の destination check
1-hop 化基本的に純利益だが、destination が `noindex` or low-quality だと loss edge case。
**修正**: 1-hop 化後の destination が noindex でないこと verify (x-robots-tag header + meta robots 両方 check)。
