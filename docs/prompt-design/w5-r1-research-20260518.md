## 主要 findings

### 1. 軸設計 — 5 軸 → **7 軸に拡張** 推奨

Cowork 草案 (A-E) は「ユーザー helpfulness」と「Author E-E-A-T 紐付け」が欠落、HCU 2026 主スコア。

**追加軸**:
- **F. Helpfulness / User Task Completion**: TL;DR + 価格 + 営業時間 + 予約 URL + アクセス の 5 必須要素、article 1 本で意思決定完結するか
- **G. Author-Content Binding**: 本文中に著者一人称段落 (「私が 4/19 訪問した際」) が **1 本につき 1 段落以上** = Experience signal proxy、AuthorBox 単独では足りない

**Threshold 確定値**:
| 軸 | PASS 基準 |
|---|---|
| A 実訪問 | hero+body 実写 ≥ 40%、firsthand 段落 ≥ 1 |
| B プレス言換 | semantic cosine < 0.60 vs 公式 release、≥ 0.70 削除候補 |
| C Wikimedia | 画像 ≤ 50% かつ独自洞察 block ≥ 1 |
| D firsthand 追記可能性 | R11 動画 / Takashi library で素材在庫あり |
| E AI fingerprint | em-dash < 0.6 / 100w + boilerplate phrase ("plays a crucial role", "leverage" etc) ≤ 2 hit |
| F Helpfulness | 5 必須要素中 4/5 |
| G Author binding | firsthand 段落 ≥ 1 |

### 2. Automated audit script 実装

| 検出 | 推奨手法 | 自動化率 |
|---|---|---|
| Semantic similarity | `@xenova/transformers` (all-MiniLM-L6-v2、local 23MB、API 費 0)、cosine threshold 0.70 | 100% |
| Image source | EXIF + filename pattern (wikimedia_*, IMG_* iPhone), reverse search は spot check | 90% |
| AI fingerprint | em-dash density + boilerplate regex (18 signal) 自前実装、Originality.ai は 82% + light edit で 20-30% 落ち、$30/1000 page = コスパ悪 | 80% (自前で十分) |
| Perplexity/burstiness | GPTZero false positive 高、non-native 罠、参考値のみ | 推奨せず |
| Firsthand 段落 | 「I visited / 訪問 / 撮影」regex + 日付 entity (BERT-NER) | 80% |

**OSS 組み合わせ**: `semantic-relevance` npm (MIT) + Screaming Frog (license) + 既存 jpn-article-audit Skill 統合、`@xenova/transformers` で完全 local 化。SaaS 不要。

### 3. 削除 bucket sub-routing

```
替え記事あり (同 IP / 同 cafe の新 article)   → 301 redirect (link equity 移譲)
完全に役目終了 (期間限定 collab post-event)   → 410 Gone (48h で deindex、404 より高速)
書き直し前提 (薄いが価値あり)                 → noindex frontmatter + sitemap 除外 (live 維持で GSC 監視)
```

**反映期間 (2026 実測値)**:
- noindex 再 crawl 後 1-7 日で index drop
- 410 初回 crawl 48h 以内 deindex
- HCU site-wide score: 累積効果 3-6 ヶ月、上位 20 page 改善で 6 週で 70% recovery 報告

**運用**:
- sitemap 落とすタイミング = 即時 (410/noindex deploy 同 commit)
- robots.txt block 禁止 (noindex tag 読めなくなる)
- 内部リンク除去必須 (related-articles.ts + MDX 内 `[]()` link grep)

### 4. 修正 bucket Information Gain block

Cowork 草案 (実体験 / 独自比較 / 価格表 / 1 時間プラン) + **追加 8 種**:

1. 訪問日時付き before/after 写真 (混雑差等)
2. 言語別 menu / sign 翻訳表 (公式英訳ない場合)
3. 失敗談 + 教訓
4. Dated project log (weekly 訪問ログ)
5. Pricing comparison vs 海外価格
6. アクセシビリティ実測 (車椅子/ベビーカー/English staff、公式 page 無い)
7. 限定 goods 完売タイミング報告
8. Original survey / mini-poll (Threads N=50 でも可)

**Threshold**:
- 低品質判定 reverse には **≥ 3 block / article 追加** (Adstimate 2026 audit data)
- 1200 word minimum は **secondary**、IG block 3 個あれば 900 word でも recovery 事例
- **"30% Rule"**: site 全体で **≥ 30% article** が「他 site にない情報」を含む必要

### 5. 維持 bucket 判定 + audit cycle

判定: 7 軸中 **≥ 5 PASS** で維持

Audit cycle:
- **Quarterly**: 全 article status code + indexing check
- **Bi-annual**: 7 軸 full re-score、collab 期限切れ記事の 410 化
- **Trigger-based**: GSC impression 0 が 90 日継続 → 強制 re-audit
- **Core update 直後 2 週**: top 20 page full review (HCU 反映期間と一致)

維持 bucket でも鮮度 check 6 ヶ月毎必須、collab 終了済は自動降格 (修正 post-event reframe or 削除 410)。

## Cowork 草案改善具体案 (W5 framework v2)

```markdown
## W5 Audit Framework v2 (5 → 7 軸)

### Score per Article (0-7 PASS count)
- [ ] A. 実訪問 evidence (実写 ≥ 40%, firsthand ≥ 1 段落)
- [ ] B. Press 言換度 (cosine < 0.60 vs 公式)
- [ ] C. Wikimedia 比率 (≤ 50% かつ独自 block ≥ 1)
- [ ] D. Firsthand 追記可能性 (R11 / Takashi library 在庫)
- [ ] E. AI fingerprint (em-dash < 0.6/100w, boilerplate ≤ 2)
- [ ] F. Helpfulness (TL;DR/価格/時間/予約/access の 4/5)
- [ ] G. Author binding (一人称段落 ≥ 1)

### Bucket Routing
- ≥ 5 PASS → 維持 (半年 cycle 再 audit)
- 3-4 PASS → 修正 (IG block ≥ 3 追加、再 score)
- ≤ 2 PASS または A+B+C+G 全 FAIL → 削除

### 削除 sub-routing
- 替え記事あり → 301
- Post-event collab → 410
- 書き直し予定 → noindex

### 自動化分担
- 自動: B (cosine), C (image), E (regex), F (frontmatter)
- 半自動: A (firsthand regex + 手動), G (一人称 regex)
- 人間判断: D 在庫照合, 削除最終承認
```

## ★ fab 検出考慮
- B cosine は press release URL を article 内記録 or WebSearch で再 fetch、推測 ban
- D 在庫照合は R11 動画 frame + Takashi library 実在確認、推測禁止
- 自動化不可な軸は「人間判断」明示
