## Build mechanism note

Sitemap is generated by **`app/sitemap.ts`** at build time using `MetadataRoute.Sitemap` (Next.js 16 native API). The article portion comes from `getAllArticles()` in `lib/articles.ts`, which presumably reads `content/articles/*.{md,mdx}`.

Filter / exclusion logic identified:

1. **Lines 83–97:** Empty-category hub pages are dropped (and `robots=noindex` on those routes) — prevents thin-hub indexing attempts.
2. **Line 147:** Final `filter((u) => !u.url.includes('/tags/'))` strips every `/tags/*` URL even though `tagPages` is computed earlier — defensive double-belt for tag noindex.
3. **`getAllArticles()`** (not directly inspected here) is presumed to skip `.deprecated`-suffixed files; the parity result confirms this empirically (the `blue-lock-tokyo-skytree-cafe-2026.mdx.deprecated` file is **not** in the sitemap, while the active `.md` version is).
4. **Line 66–68 comment:** `/search` deliberately omitted (`robots=noindex` on the page).
5. No `draft: true` / `robots: noindex` filter inside the article mapper — none of the 77 articles use those frontmatter keys, so absence of filter is currently harmless.

## Top 5 anomalies / indexing-blocker root causes

Even though the diff is clean, these are the most likely **future** indexing risks worth monitoring:

1. **Apex hostname does not resolve.** `japanpopnow.com` (no hyphens) returns curl exit 6. If any external link or social post used that variant, those clicks 404. Confirm DNS and ensure the canonical `www.japan-pop-now.com` is the only one ever published. (If the apex `japan-pop-now.com` *with* hyphens fails too, we'd want a 301 to www — should re-test that variant in next sweep.)
2. **No `getAllArticles()` filter for `draft`/`noindex`.** All 77 articles are healthy today, but the day someone adds `draft: true` to a frontmatter, that article will still appear in the sitemap. Recommend adding `.filter((a) => !a.draft && a.robots !== 'noindex')` to the article mapper.
3. **`.deprecated` suffix is implicit, not enforced.** Parity holds because `getAllArticles()` filters by `.md`/`.mdx` extension — but `*.mdx.deprecated` works only by filename accident. A future `.draft.mdx` file would leak into the sitemap if the regex is permissive. Verify in `lib/articles.ts`.
4. **No `/articles` listing hub in sitemap.** If an `app/articles/page.tsx` route exists (the `app/` listing showed an `articles/` directory), it's an orphan from a sitemap perspective. Either add it to `staticPages` or `noindex` it explicitly to avoid Google discovering and de-prioritising it as orphan.
5. **15 entries share `2026-05-05` lastmod** (all hub pages keyed off `latestArticleDate`). This is correct behaviour but produces a sitemap that Google may interpret as a bulk-update — repeated hub-only `lastmod` churn can throttle crawl budget. Acceptable; just be aware that *every* article publish bumps every hub's lastmod.
